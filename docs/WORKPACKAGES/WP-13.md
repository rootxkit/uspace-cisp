## What to build

- Chaos e2e (`test/e2e/chaos_test.go`, compose-driven, each case
  printing what it observed): PostgreSQL stopped 60 s during reads and
  a publication (reads stale-marked, PUT 503, recovery clean, no lost
  change); NATS stopped 60 s (scan delivers; no duplicate); `api`
  killed mid-publication (no partial version; the client's retry with
  the same `If-Match` succeeds or gets 412 with the new etag — never a
  second version of the same content); `deliver` killed mid-batch
  (exactly-once delivery observed at the subscriber); the subscriber
  down 30 min then up (the retry schedule's attempts match
  `NextAttempt` within jitter); a 20 MB publication under 50 concurrent
  public readers (p99 of `HEAD` under 50 ms, reads unaffected). Each
  prints a table in the step summary; the job runs on `main` and on a
  `chaos` label.
- Rate limits and cache at Caddy: a compose profile with Caddy using
  the reference copy `deploy/caddy/Caddyfile.snippet` (the deployment
  repository composes the real one, M25/D1; a diff between the two is
  a finding for the owner, not something to fix here); a test that the
  public `GET` is served from Caddy's cache on the second request
  (header), that `/metrics` is not routed (404 from Caddy), that
  `/basemap/*` is served with range support and long cache headers
  from the volume, that with `client_auth verify_if_given` the ANSP
  route without a client certificate reaches `api` **without** the
  subject header and is refused there in `required` mode (403
  `mtls_required`), and that a forged `X-Client-Cert-Subject` on any
  route, with or without a certificate, never reaches `api`.
- `make conformance`: when `LAB_DIR` has `conformance/cisp/`, run it
  against the compose stack and fail on a failure; otherwise print
  "lab conformance suite not present at <path>: skipped" and exit 0
  with a step-summary line (never a silent pass). CI job on `main`
  only.
- Supply chain: `syft` SBOM attached to both images, cosign keyless
  signing in the image job, `cosign verify` in `deploy/deploy.sh`
  (pull by digest, verify, `compose up`), Dependabot for Go modules,
  npm (`pnpm-lock.yaml`) and Actions (weekly, grouped).
- Compatibility: the `Sunset` and `Deprecation` header plumbing on the
  router (no deprecated operation yet; the test marks one and checks
  the headers), and `docs/RELEASING.md`: how a `/v1` additive change is
  made, how a `/v2` would be served beside `/v1` for 12 months, how a
  `uspace-core` major is taken (the vector-pinned behaviour change
  procedure), the tag and CHANGELOG rules, the image digest in the
  release notes.
- Runbooks: deploy and roll back (by digest), backup and restore with
  the weekly restore test (`cispctl verify-backup` restores the latest
  dump into a scratch database and checks `datasets.current_version`
  and the hash chain), key rotation (ring overlap, JWKS, when to drop
  the previous key), stale publisher (what the console shows, who to
  call, nothing to do in the CISP), subscriber storm (suspend, notify
  the client, resume).
- Optional (Q22): on-the-fly `X-CIS-Signature` for filtered reads,
  bounded by a per-instance signing rate and off by default.
- `v1.0.0`: CHANGELOG complete for `0.1.0` (C-M1), `0.2.0` (C-M2),
  `1.0.0` (C-M3); `api/openapi.yaml` `info.version: 1.0.0`; the owner
  tags.

## Safety notes

A chaos test that passes because nothing happened is the trap (E-02):
each case asserts the degraded observation first (the stale header
seen, the 503 seen, the scan counter moved) and the recovery second.
Record the image digest and the compose file hash with every run
(E-05).
