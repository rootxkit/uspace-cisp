## What to build

- Intake: `PUT /v1/publications/zones` with `Content-Type:
  application/vnd.ed269+json`: `ed269.Parse` (strict, core's limits
  with the publication byte cap), `ed318.FromED269(doc, meta, lang)`
  with `meta.Issued = now`, `meta.Provider = [{text: <publisher client
  id>, lang: "en"}]` and `lang = "ka"` by default (`?lang=` overrides;
  the text language of the single-string ED-269 fields), then the
  normal `zones` rules of WP-3 on the mapped collection. What is stored
  as the version's **body** is the mapped ED-318 bytes (`ed318.Export`),
  so every consumer sees ED-318; the original ED-269 bytes are kept in
  `publications.source_body` with `source_content_type` (a WP-1 column
  added here by a migration `000N_source_body.sql`) and the publisher's
  signature is over the **original** bytes (verified before parsing, as
  F1). The publication result says `mapped_from: ed269` and lists the
  mapping warnings (texts carried under `extendedProperties.ed269`).
  A refusal lists `ed269.Problems` by their ED-269 paths.
- Export: `GET /v1/{dataset}/versions/{v}?format=ed269` for `zones` and
  `restrictions`: `ed318.Parse` of the stored body, `ed318.ToED269(fc,
  lang)`, `ed269.Export`; 406 `not_representable` naming the field when
  the version holds what ED-269 cannot (USPACE, DAR, daylight events,
  two-layer zones) — so `restrictions` is almost always 406 and the
  OpenAPI says so; `Content-Type: application/vnd.ed269+json`,
  `X-CIS-Signature` over the exported bytes, `X-CIS-Mapped-From:
  ed318`. For a version that was imported from ED-269, `?format=ed269&source=true`
  returns `source_body` verbatim with `X-Publisher-Signature`.
- `cispctl ed269 convert --to ed318|ed269 [--lang ka] < in > out`: the
  same mapping offline, with problems on stderr and exit 1 — the tool
  the authority planner can use before the authority console exists, and
  the lab's check for Q6.

## Safety notes

The mapping is core's; this WP must not add a conversion of its own
(no unit change, no spelling fix, no default reference). If a file does
not map, it is refused with core's reason. The stored version is the
mapped ED-318, because that is what consumers judge; the original is
kept only as evidence of what the authority sent.
