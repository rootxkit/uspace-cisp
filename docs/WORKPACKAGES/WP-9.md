# WP-9: the web scaffold (Next.js on `uspace-ui`)

Branch `feat/WP-9-web-scaffold`. Milestone C-M1 (with U-M1). Owns
exclusively: `web/` (everything), the `web` CI job in
`.github/workflows/ci.yml` (added as its own job with a `web/**` path
filter), the `web` service in `deploy/compose.yml` (enabling the

and bump to `0.1.0` at U-M1. WP-10 and WP-11 build pages on this
scaffold: open the PR as soon as `pnpm build` passes in CI.

## What to build

- `web/`: Next.js (App Router, `output: 'standalone'`), React,
  TypeScript `strict: true` (plus `noUncheckedIndexedAccess`), Tailwind
  with the kit's theme, `@rootxkit/uspace-ui` from npmjs with an exact
  pin (`0.1.0-rc.N`, then `0.1.0`; never a `github:` tag, Q14, M32),
  `pnpm` with `packageManager` pinned in `package.json`, a committed
  `pnpm-lock.yaml` and `pnpm install --frozen-lockfile` everywhere
  (M34). API types are generated by the kit's `uspace-ui-gen-api`
  (ui Q14), never hand-written.
- Layout: `app/[locale]/(public)/` (WP-10 fills it) and
  `app/[locale]/(console)/` (WP-11), `app/_bff/` routes, `src/api/`
  (generated `types.ts` from `../api/openapi.yaml` by
  `openapi-typescript`, plus a thin typed `fetch` wrapper that reads
  `NEXT_PUBLIC_API_BASE_URL` on the client and `CISP_API_INTERNAL_URL`
  on the server), `src/i18n/` (`ka.json`, `en.json`, the kit's provider;
  a test that both catalogues have the same keys), `src/branding.ts`
  (reads `CISP_BRANDING_FILE` at build or start: name, logo, contact;
  defaults are code names, never a real organisation's), `middleware.ts`
  (locale routing `/ka`, `/en`, default from `Accept-Language`, `ka`
  first).
- The BFF (`app/_bff/login/route.ts`, `logout`, `proxy/[...path]`; three
  routes, no `ws-ticket`): the kit's helpers; login posts credentials to
  `/v1/console/session` server-side and sets the **`uspace_session`**
  cookie (`HttpOnly; Secure; SameSite=Strict`) with the token and the
  **`uspace_csrf`** double-submit cookie (M21); the proxy forwards
  `/_bff/proxy/*` to `/v1/console/*` with the cookie as the bearer and
  requires `X-CSRF-Token` on mutating methods; nothing else runs
  server-side. The WebSocket is not proxied: the kit's `useFeed`
  connects `WS /v1/stream` same-origin and the cookie rides the upgrade
  (M22); a `4401` close means "re-login". `web` holds no
  signing key, no database URL, no NATS URL (a test greps the built
  server bundle's env usage for `CISP_DATABASE_URL`, `CISP_NATS_URL`,
  `CISP_SIGNING` and fails if present).
- Lint: the kit's ESLint config plus two project rules in
  `web/eslint-rules/`: `no-geometry-import` (forbids `@turf/*`, `geojson`,
  `proj4`, `h3-js`, `@mapbox/*` except what the kit re-exports,
  `geolib`, `cheap-ruler`, any package with `geodesy` in its name) and
  `no-server-business-logic` (files under `app/_bff/` may import only
  the kit's BFF helpers, `next/server` and `src/api/types`; no other
  `app/**/route.ts` may exist). Both rules have a failing fixture in
  the test.
- Fonts and basemap (M38): the kit's Noto Sans + Noto Sans Georgian
  through `next/font/local` (self-hosted in the image, no runtime
  fetch); the map loads the self-hosted PMTiles bundle from `/basemap/`
  (served by the deployment's Caddy from the shared volume the lab
  builds, `docs/PLAN.md §11`; in `compose.yml` a local volume the
  developer fills from the lab release artefact, documented in
  `web/README.md`); `next.config` sets the kit's CSP (`connect-src
  'self'`, `font-src 'self'`, `worker-src blob:`), so no third-party
  tile or font request ever leaves the browser; a Playwright smoke test
  renders a Georgian string, asserts the computed font family and
  asserts that every network request in the run stayed on the origin.
- `deploy/Dockerfile.web`: `node:22-alpine` builder with `corepack`
  enabling the pinned `pnpm` (`pnpm install --frozen-lockfile`, `pnpm
  build`), runner with the standalone output, non-root, port 3000;
  health at `/healthz` (a static route). The `web` compose service with
  `NEXT_PUBLIC_API_BASE_URL` and `CISP_API_INTERNAL_URL`.
- CI job `web` (path-filtered to `web/**`, `api/openapi.yaml`): `pnpm
  install --frozen-lockfile`, `pnpm generate` then `git diff --exit-code
  web/src/api`, `pnpm lint`, `pnpm typecheck`, `pnpm test` (vitest),
  `pnpm build`, Playwright smoke against `next start` with
  `/public/v1/*` mocked by a small fixture server
  (`web/test/mock-api.mjs`) — browsers cached by `actions/cache` keyed
  on the Playwright version. The image job of WP-0 gains the `web`
  image step.

## Tests

- i18n: catalogue keys equal; no hardcoded display string in `app/`
  (an ESLint rule from the kit if it has one, else a grep test for
  JSX text nodes outside `t()` in this repo's pages).
- Lint fixtures: a file importing `@turf/boolean-point-in-polygon` fails
  `no-geometry-import`; a `route.ts` outside `_bff` fails
  `no-server-business-logic`; the BFF files pass.
- BFF: login sets `uspace_session` with the cookie flags and
  `uspace_csrf` (unit test on the route handler with a mocked `fetch`),
  the proxy forwards the bearer and refuses a mutating request without
  `X-CSRF-Token` matching the cookie, `logout` clears both cookies and
  calls `DELETE /v1/console/session`; no route exists under
  `_bff/ws-ticket` (a test asserts the three-route list).
- Bundle check: the built server bundle contains none of the forbidden
  env names.
- Playwright: `/ka` and `/en` load, the Georgian glyphs render with the
  kit's font, the locale switch works.

## Safety notes

The only safety rule for `web` is that it cannot become a second place
where airspace is judged or where a credential lives. The two lint
rules and the bundle check are that rule in executable form; they are
not optional and they fail CI, not warn.
